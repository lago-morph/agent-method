# Specify corner cases in use cases

A use-case draft is not done when the happy path is written. Specify
what happens with nothing (empty list, empty or whitespace-only
content), with too much (more items than fit, text larger than its
area), and design the test data to show off each corner case
deliberately.

Grounding (2026-08-30): Jonathan's markup on the Initial UI use case —
what happens with no ideas, with an over-full list, with over-long
text, with empty/whitespace ideas, and what the test data includes to
exercise all of it.
