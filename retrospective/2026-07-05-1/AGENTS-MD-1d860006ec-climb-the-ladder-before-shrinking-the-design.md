# agent instruction

**Climb the ladder before shrinking the design.** "When the user says a proposal is too complex, too restrictive, or jumping ahead, do not respond with a smaller proposal at the same level. Move up one level - from implementation to design, from design to framework, from framework to requirements - and get the higher level agreed before descending again."

*Grounded in: two consecutive plan rejections in the methodology-reset session.*

# justification

The session lost its two largest work products to this exact failure. A full reset plan (one-page method, use-cases-only, fixed file layouts) was rejected not for its size but for its altitude: it made implementation decisions while the question of what to build was still open. The corrected response was not a smaller plan — it was moving up to a framework conversation, and when that also proved premature, up again to requirements. Each failed descent cost a complete authoring-review cycle (hours of session time and stakeholder attention); the eventual requirements-first pass converged in one round. The marginal cost of the rule is a single question asked before drafting: "is the level above this one settled?"
